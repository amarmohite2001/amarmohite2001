# Spec-driven work

- Non-trivial changes start from a spec in `project-docs/specs/`. Copy `_template.md` and fill in the user story and acceptance criteria before writing code.
- Trivial edits, such as a typo in `data/content.ts`, do not need a spec.
- Implement against the spec's acceptance criteria. If the spec and the code disagree, note it in the spec's Activity log instead of silently changing either one.
- Mark a spec Done only when every Definition of Done box is checked.

Process details: [`project-docs/specs/README.md`](../../project-docs/specs/README.md).
